# App Store screenshots

Generated by `tools/store-screenshots.cjs`. Two sets, which is the whole
requirement — App Store Connect auto-scales every smaller size from these:

| Folder | Family | Pixels |
|---|---|---|
| `iphone-6.9/` | iPhone 6.9″ | 1320 × 2868 |
| `ipad-13/` | iPad 13″ | 2064 × 2752 |

Portrait, RGB, no alpha channel (App Store Connect rejects alpha). Apple
accepts 1–10 per family.

## Regenerating

```bash
pnpm dev                                   # serves on 5173
node tools/store-screenshots.cjs iphone
node tools/store-screenshots.cjs ipad
```

Env overrides: `SUNDER_PORT` (default 5173), `SUNDER_SHOT_DIR`,
`SUNDER_TURNS` (default 14), `SUNDER_CHROMIUM` (explicit browser binary, for
environments where the installed build and the pinned playwright disagree).

**Runs are not reproducible.** `newGame()` takes an explicit seed but the AI
rolls live, so the same seed yields a different match on a different browser
build — on one, Kharzul won outright at turn 10. If a run reports `match
ended`, lower `SUNDER_TURNS`. Review the frames each time rather than assuming
the previous composition came back.

The rig captures with `?fx=full`, which is what keeps bloom, vignette and
shadows in the frame: headless Chromium runs on SwiftShader, which trips the
renderer's software-GL branch and strips the post-processing before the first
frame.

## The frames

| # | Shows |
|---|---|
| 01 | Title and the eight factions |
| 02 | Match setup — difficulty, board size, world type |
| 03 | Faction briefing — passive, unique unit, opening moves |
| 04 | Mid-match board — four factions' borders, cities, units |
| 05 | Commander-slain card |
| 06 | Research tree |
| 07 | City planner overlay — projected building value per tile |

05 depends on a kill happening during the simulated turns, so it is not
guaranteed on every run.
