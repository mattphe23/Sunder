## AI Playtest Lab design (phase 4, in progress)
- User said "on demand for now" → NO cron/Heartbeat needed. Admin clicks "Run playtest" in dashboard → server job runs in-request (async, fire tRPC mutation, poll status via query). Autoscale 15-min request timeout is plenty for a headless match.
- Architecture per automation skill: WebDev in-app on-demand job, built-in LLM via server/_core/llm.ts (invokeLLM). No Manus scheduled tasks.
- Engine is client code (client/src/game/core/*) but pure TS — server tests already import it headlessly (engine.sim.test.ts pattern). Server can import the same engine for playtest jobs.
- Design: playtest_runs table (id, status queued/running/done/failed, params json, createdAt) + playtest_reports (runId, matchSummary json, feedback json: balance/clarity/fun/bugs arrays + scores, llmModel, rawLog key?). tRPC adminProcedure routes: playtest.start, playtest.list, playtest.get.
- LLM plays turns: each turn send compact state summary + legal action list → LLM picks action id (JSON schema). Fallback: scripted AI (existing aiTakeTurn) if LLM errors/timeouts. To bound cost/time: LLM plays ONE tribe, scripted AI plays others, cap ~15-20 turns, then LLM writes final structured feedback report.
