# Sunder — iOS build

The App Store build is the same web build running in a WKWebView. There is no
second codebase: everything visual and interactive lives in `client/`, and this
folder only carries what a web build cannot express — the bundle identity,
the launch screen, the icon, and the web view's behaviour.

## Build it

```bash
pnpm ios:sync     # regenerate icon + splash, build, then cap sync ios
pnpm ios:open     # opens ios/App/App.xcworkspace in Xcode
```

`cap sync` copies `dist/public` into `ios/App/App/public/`. That copy is
generated and git-ignored — never edit it, and never commit it.

`pnpm icons` rasterises the brand sigil with headless Chromium, so the first run
on a new machine needs the browser binary once:

```bash
pnpm exec playwright install chromium
```

Playwright is a devDependency, so `pnpm install` covers the rest. If the browser
is missing, the script says so and names this command instead of failing on a
module-resolution error. The committed icon and splash are already correct, so a
clone that skips this step can still build — `cap sync` only needs `pnpm build`.

Everything up to the Xcode step runs anywhere. Archiving and uploading needs
macOS with Xcode and a signing identity, so those steps have to happen on a Mac.

## What is already configured

| Thing | Where | Why |
|---|---|---|
| `webDir: dist/public` | `capacitor.config.ts` | vite emits the client there; the Express bundle beside it is server-only and must not ship inside the app |
| `backgroundColor: #141433` | `capacitor.config.ts` | Babylon clears transparent and the sky is a CSS gradient, so the native colour shows for one frame at launch. Without this the app opens on a white flash. |
| `contentInset: never` | `capacitor.config.ts` | the app handles insets itself via `env(safe-area-inset-*)` and asks for `viewport-fit=cover`; letting the web view also inset applies the padding twice |
| `scrollEnabled: false` | `capacitor.config.ts` | the board is dragged and pinched constantly — rubber-banding reads as the map coming loose |
| Light status bar | `App/Info.plist` | the app is a dark indigo void end to end. Set app-wide rather than per view controller so it is right from the launch screen, with no StatusBar plugin. |
| Icon + splash | `App/Assets.xcassets` | generated by `pnpm icons` from the same procedural sigil as the in-app brand mark (`client/src/game/ui/Brand.tsx`), so the home screen and the game cannot drift apart. `ios:sync` regenerates them, so they are never stale — and they are committed, so a fresh clone can build without running anything first. |
| Flat splash ground | `scripts/gen-app-icons.mjs` | the splash is the flat void colour, not the sky gradient. A 2732² gradient encodes to ~1.6MB of PNG (no runs to compress) and three of them broke a deploy size limit; flat crushes to ~60KB. It also matches `backgroundColor`, so there is no seam between the launch screen and the web view. |

## Before submitting

- [ ] Set the team and bundle identifier in Xcode (`com.sunder.livingforge` is a
      placeholder until the real one is registered).
- [ ] Bump `CFBundleShortVersionString` / `CFBundleVersion`.
- [ ] Run on a device with a notch and one without. The layout is verified at
      393×852 with simulated insets, which is not the same as the real thing.
- [ ] Check the launch → first frame transition for a flash. If one appears, it
      is the gap between the launch screen and Babylon's first render, not the
      background colour.
- [ ] Decide what happens with no network. Solo, hot-seat and challenges are
      fully offline; online duels and the leaderboard are not, and should fail
      with an explanation rather than a spinner.
- [ ] If in-app purchases ship, they need a StoreKit plugin and App Store
      Connect products — the current store is Stripe and web-only. See the
      monetization thesis: use Apple IAP for anything bought inside the app.
